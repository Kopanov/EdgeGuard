Production on the edge

Every version is deployed from the main branch. The health endpoint reports the running commit, so what runs is always traceable to code.

Repeatable rebuilds

Five full 730-day baselines were rebuilt from an empty database between 13 and 22 October 2026. An automated acceptance check runs after each one: 57 of 58 checks passed on 24 October (the one miss was an opt-in source that was switched off).

One-script install

A single install script with a readiness pre-check sets up the whole stack. A smoke test fits in 16 GB of RAM; the full two-year baseline needs about 48 GB.

Always fresh

Collectors run on their own schedules — OTX every 30 minutes, CISA KEV and VirusTotal every 4 hours, NVD every 8 hours — and the graph re-syncs from MISP every 72 hours.

Every answer carries its evidence

MISP is the single source of truth. Each node and relationship in the graph keeps the MISP event and attribute it came from, with its confidence and sources.

From question to explained answer

  1. Question — an analyst asks in plain language.
  2. Cypher — a small fine-tuned model writes the graph query.
  3. Guard — the query is checked before it runs: read-only, bounded, schema-valid.
  4. Bounded execution — the query runs against the live graph with limits.
  5. Explanation — verdict, graph path, sources, confidence, MISP records and next steps.

Example: one actor, two sources

Asking which techniques APT28 uses returns 169 techniques — 93 recorded by MITRE ATT&CK and 76 by AlienVault OTX (sampled 25 October 2026). Each technique links back to the MISP record it came from, so the analyst can check where every claim originated.

Graph-Augmented xAI for Threat Intelligence on Edge Infrastructure

EdgeGuard gives organisations with limited security staff transparent, auditable threat intelligence. It combines a symbolic knowledge graph with a small fine-tuned language model, runs on edge infrastructure instead of opaque cloud platforms, and turns raw security alerts into clear recommendations an analyst can trace back to their sources.

How it works

Open threat feeds land in MISP, become a provenance-preserving graph in Neo4j, and are served to analysts and to ResilMesh.

Dataset and model

Dataset v0.10

  • 3,588 core records (2,868 train / 360 validation / 360 test), plus 127 phrasing-robustness probes and 140 analyst-style questions
  • Built from six SOC question categories and 19 query patterns
  • Every query passes a four-stage validation ladder against the live graph before it enters the dataset
  • No overlap between training and test questions

Model v0.10

  • Base: Qwen3-4B-Instruct-2507
  • 4-bit QLoRA, 3 epochs, about 2 h 20 min on a single NVIDIA L4 on Ratio1 infrastructure
  • Exported as a 4-bit GGUF of about 2.5 GB for edge serving
  • Keeps a graph-returning answer form on 100% of robustness probes

Sealed benchmark

500 held-out questions, three models, 1,500 results, adjudicated blind. Result F1 compares the rows each query returns with the reference answer.

Explainability and integration

Playground

Analysts compare models side by side through the full chain: generation, guard, bounded execution and explanation.

Provenance-first answers

Graph results are compacted into a structured digest before the model explains them, so explanations cite real records. Actor lookups resolve aliases (for example "Cozy Bear" → APT29).

Integrations shipped

Wazuh CDB export, a 12-route REST API with STIX 2.1 export, and GraphQL following ResilMesh ISIM conventions.
